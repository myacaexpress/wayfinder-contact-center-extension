# Wayfinder Call Protection — automatic pilot (0.2.1)

The installed extension automatically pairs exactly one AllCalls `/take-calls` tab
with a signed-in production Wayfinder `/agent` tab in the same Chrome
profile. No per-call mode buttons. Use the same agent's accounts in both tabs.
The first pairing needs one Wayfinder agent tab. Once confirmed, opening another
Wayfinder dashboard preserves the original tab pairing.
The first authenticated pairing pins that Wayfinder account; changing accounts
requires a separate Chrome profile, not silently controlling another agent.

## Install or update

Unzip into a permanent folder. In `chrome://extensions`, enable Developer mode,
choose Load unpacked, and select the folder containing `manifest.json`. To update
an existing unpacked installation, replace that folder's files and click Reload.
Refresh AllCalls and Wayfinder afterward, and pin the green W icon.

## Automatic behavior

- AllCalls ringing, talking or wrap-up blocks new Wayfinder calls and moves an
  Available agent Offline. An existing Wayfinder call is never disconnected.
- A Wayfinder reserved, ringing, connected or wrap-up call turns AllCalls Off using
  the unique visible switch on Take Calls, verifying its `aria-checked` state.
- After two fresh idle samples, restore only availability changed by protection.
  Agent Break/Offline requests in Wayfinder and manual AllCalls switch clicks
  cancel the corresponding automatic restoration. Manager restrictions remain.
- Unrecognized UI, expired data or provider errors block new Wayfinder routing.
  Lost communication also attempts AllCalls Off while the browser is running.
  Recovery from unknown/expired state does not automatically put agents online.
- The popup displays status only. Both calling pages must stay open with the Mac awake. A visible
  Wayfinder workspace requests fresh AllCalls DOM samples even when AllCalls timers
  are throttled in the background. A paused/sleeping browser still fails closed.
  Multiple AllCalls tabs or an ambiguous initial Wayfinder pairing block with an
  explicit reason.
- Closing/uninstalling does not remove the server routing protection. Reopening
  the correct tabs recovers monitoring. Another browser can take ownership only
  after the old 30-second lease expires.

## Diagnostics

The popup shows observed AllCalls status, its delivery switch, Wayfinder provider
state, sample/sync age, tab counts, blocking reason, and the last confirmed or
failed automatic AllCalls switch. Status reads stay responsive during a pending
sync; the previous acknowledgement remains visible only within its freshness window.
The production banner and availability errors show the server's exact reason,
last successful sync, and observed status. Offline plus an expired lease is
explicitly reported as stale confirmation, not an active AllCalls call.
Diagnostics persist only fixed enum states and timestamps, never page text.

## Verified UI and acceptance limits

The inspected AllCalls Take Calls page exposes one visible
`button[role=switch][aria-checked]`, a `Take Calls` heading and `Offline` text.
The Off switch was inspected without enabling live paid call delivery. The fixed
busy labels are Ringing, Incoming call, Talking, On a call, Dispositioning and
After-call work. Waiting is the positive online-idle label. Unknown wording blocks
routing. An off banner elsewhere in the app is not enough to assert this agent idle.

Use synthetic calls to verify actual ringing, talking, wrap-up, automatic Off and
On confirmation in both directions, manual overrides, manager restrictions,
network loss, logout, sleep/wake and multiple tabs before operational reliance.
Actual busy labels and complete live call cycles remain unverified until this test.
UI and provider latency cannot guarantee atomic cross-vendor reservation or retract
an already offered call. Closing the whole browser cannot toggle a remote service.
Use Wayfinder's status selector for manual overrides; an identical Offline write
in an external Connect client cannot be distinguished from protection's Offline.

Only fixed status enums, opaque identifiers and timestamps are exchanged. No
caller data, recordings, audio, cookies or authentication tokens enter the extension.
AllCalls calls stay outside Connect. No remote scripts or generic command execution.

## Agent controls (0.3.0)

Open the W popup to change **Automatic protection**. Off is confirmed by the signed-in Wayfinder account before it is shown as saved. It stops automatic status changes and removes this interlock's routing veto; it does not set either calling system Available, override manager restrictions, or hang up calls. The choice persists across browser restarts. Turn protection back on before relying on automatic coordination.

The single switch includes restoration after wrap-up. Both systems can be available while idle. Ringing, an active call, or wrap-up pauses the other system; completion restores prior availability. Wayfinder restoration remembers a call that began after confirmed Available status, waits for that same call's completed wrap-up and fresh idle checks, and uses the ordinary availability eligibility checks. Manual Break/Offline, a manager restriction, stale status, or turning protection off cancels pending restoration. It never automatically completes wrap-up.

Version 0.3.2 automatically stands by when no AllCalls tabs exist or only its login page is open. Wayfinder remains usable without changing the protection toggle. Opening Take Calls resumes fresh status checks. Other AllCalls pages, duplicate calling tabs, and an unreadable open calling page remain explicit connection errors; they are not treated as logged out. After updating the extension, refresh idle calling pages to reconnect their content scripts.

Version 0.3.3 removes unrecorded client-side Off commands on transport or pairing errors. AllCalls refuses automatic switch clicks while ringing, talking, wrapping, or unreadable. Server-owned pauses survive transient unknown observations within the same document session; a new document session or expired lease does not silently restore AllCalls after an unobservable manual-action gap. The popup retains the last switch attempt across extension reloads and explains an unconfirmed restoration. Queued Connect status choices are never overwritten by the interlock. These guards do not provide atomic cross-provider reservation or replace live tests in both directions.

## Public UHC Summary of Benefits capture (local prototype, 0.3.4)

W → **Capture public benefits PDF (local research)** opens a separate extension page.
Generate a five-minute, single-use code at `http://127.0.0.1:8768/capture.html`, then
paste it into W. The code binds the full plan ID, year and public UHC alphadog URL.
Click **Download public PDF and verify** to request optional UHC/loopback access.
Requests omit credentials and reject redirects; no cookies or calling-tab content
are collected. If UHC denies the extension request, use the normal Chrome PDF
viewer to save the public PDF and choose **Verify saved PDF and cache** instead.
This path needs only optional loopback access. No patient documents.

The local backend checks PDF type, size, year, contract/PBP/segment, and evidence
spans before writing the existing 24-hour document cache. Wrong identity/year,
expired/replayed codes, arbitrary websites and oversized/non-PDF bodies fail.
Cache records identify browser-assisted capture and its supplied source URL; the
upload is not cryptographic proof of publisher authenticity. PCP network remains
pending. Capture is independent of call-protection settings and message handling.

After an authorized update, the existing installed extension must be reloaded to show the
new capture page. This is a local research integration, not a production release.

## Integrity Verify pilot (0.3.5)

The W popup's **Enable Integrity Verify access** button requests optional access
only to `https://connect.integrity.com`. Granting access does not run a check.
Wayfinder's authenticated pilot creates a bounded job from an owned, saved MARx
intake. The extension reuses one exact contact overview tab or opens that contact in a
new inactive tab, without navigating existing unrelated contacts. It waits for
the correct page to finish loading and compares the signed-in Profile menu NPN with the server-bound account before claiming the
single-use job. It rechecks the account and route before opening Verify, then
compares the dialog's first name, last name, birth date and MBI before clicking
**Run Eligibility Check**. Empty, conflicting or ambiguous fields block the job;
the adapter does not fill blanks and treat those values as independent proof.

Only the fixed prepare/claim messages are bridged through the signed-in Wayfinder
page; tokens, generic endpoints and arbitrary scripts are not accepted. Claimed
identity fields exist only in memory for this action and are not logged or stored.
The adapter reports **pending**, never verified. Wayfinder checks for a fresh
saved eligibility result separately; a click alone proves no Medicare, Medicaid
or LIS eligibility. Server job claims prevent replay across browser reloads.
Call-protection settings and status handling remain independent.

Local synthetic DOM and mocked Chrome tests cover this integration. A refreshed
extension and authenticated synthetic end-to-end acceptance are still required
before claiming that live Integrity verification succeeds.

### Saved medications and doctors (0.3.6)

After Integrity site access is enabled, selecting a saved Integrity contact in
standalone Wayfinder Chat Mode automatically imports the contact's saved Medical
Profile lists. No per-medication confirmation is needed. The reader opens and
closes its own temporary background tab; it never changes a client record or a
user's existing Integrity tab. Missing, incomplete or oversized lists are reported
in chat and can be retried. Imports stay in memory; changing contacts clears them.
Medication candidates and conditional costs are shown automatically. Provider
directory candidates are **not** verified MCP network participation.

Install/update the packaged 0.3.6 extension and refresh Wayfinder. Optional Integrity
access is still granted only by the explicit button in the extension popup.

## Popup connection recovery (0.3.7)

Integrity Verify access appears directly below Automatic protection. Diagnostics
and research tools are collapsed below the primary controls. If a fresh install
finds multiple Wayfinder workspaces, choose the intended workspace in the popup
before changing protection. The server still confirms the setting and enforces
the previously paired account; choosing another tab cannot switch accounts.

## Opt-in protection (0.3.8)

New installations start with Automatic protection Off. Enable it explicitly in
the popup to begin coordination. Existing saved On/Off choices are preserved.
Integrity access remains separate and can be enabled while protection is Off.

## Complete saved health lists (0.3.9)

The read-only import now includes counted Pharmacy cards (name, address, available
phone and Primary label) and Conditions rows (saved name), alongside prescriptions
and providers. All four sections must be loaded with matching counts; missing or
unsupported sections block the whole import instead of reporting empty lists.
Explicit loaded empty sections are supported. Saved labels do not verify a
diagnosis, pharmacy network, preferred status, coverage or costs.

Requires the companion Wayfinder web update to display the new fields. Older
extensions receive an update prompt in the new web UI rather than a misleading
complete result. All lists remain contact-scoped, memory-only context, excluded
from AI/research and Call Info write-back. No additional host permissions.
Automatic protection remains Off by default and independent of Integrity access.

## Recognizable workspaces (0.3.10)

The protection selector labels the current page **This tab**, the confirmed pairing
**Paired**, and each workspace by role, window number and tab position (counted
from the left). An initial pairing prefers the current Wayfinder tab; an existing
pairing stays intact. **Go to selected tab** activates its tab and window without
changing protection. Closed or navigated-away tabs cannot be targeted.
Open pages are not proof of a signed-in session: the normal authenticated server
confirmation and account pin still apply. No new permissions or account data.
Integrity Sync is separate and does not require protection or workspace selection.

## Profile account parsing (0.3.11)

Reads the single visible NPN row in the Integrity Profile menu, including the
layout where the following Account navigation label is adjacent in textContent.
Health import and Verify share this parser. Missing, hidden, malformed or ambiguous
NPN rows still block, and the observed value must exactly match the server-bound
account. No permissions changed. Reload the unpacked extension and refresh
Wayfinder after updating; a website deployment alone cannot update unpacked files.
